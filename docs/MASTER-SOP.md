# Aviation Clarity™ Master Operating SOP

## 1. Intake
Capture one concrete audience problem. Record persona, context, desired outcome, urgency, existing workaround and willingness to pay.

## 2. Research
Use authoritative and primary sources first for aviation facts. Record source URL/title, publication/update date, claim supported and verification date.

## 3. Risk classification
Classify every claim: general education, regulatory, operational, aircraft-specific, medical/wellness, financial/business, or safety-critical. Escalate high-risk claims.

## 4. Learning transformation
Convert verified concepts into multiple modalities: plain language, technical definition, analogy, visual model, scenario, memory hook, retrieval practice and instructor prompt.

## 5. Content production
Create a canonical source asset first. Derive video, podcast, article, email, short-form, social, worksheet and quiz from the approved source asset.

## 6. Productization
When a problem recurs, create the smallest useful paid tool: checklist, template, assessment, planner, toolkit, course, membership or productized service.

## 7. QA
Check factual accuracy, source support, stale information, regulatory language, safety implications, accessibility, plagiarism/copyright risk, and unsupported AI claims. Block publication when required review is incomplete.

## 8. Approval
Assign human reviewer for safety-critical, regulatory, operational, aircraft-specific or medical content. Store approval status and reviewer/date.

## 9. Publishing
Publish only approved assets. Maintain canonical URL, version, source set, update date and correction path.

## 10. Distribution
Repurpose approved assets across YouTube, podcast, SEO, email, social and lead magnets. Maintain a single source of truth to prevent contradictory derivatives.

## 11. Measurement
Track impressions, qualified traffic, engagement, lead conversion, product conversion, revenue, refunds and content production time.

## 12. Learning loop
Every week rank topics by audience pain, evidence, demand, conversion potential and production effort. Promote winners; retire weak ideas.

## Definition of done
A feature is not done when code exists. It is done when it builds, tests, is documented, is observable, handles failure, and has been verified in its target environment.
